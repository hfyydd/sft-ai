## 2. 基座选型(本次综合的核心变更)

### 2.1 WebBrain 核实结果:不作为 fork 基座

外部提案建议 fork [webbrain-one/webbrain](https://github.com/webbrain-one/webbrain)。核实(2026-09-30,含 GitHub API 与 raw 文件验证):项目真实存在且非常活跃(~1.1k star,当天仍有 push,v37.0.1),功能描述大体吻合——侧边栏 chat、Ask/Act/Dev 三模式、Act 走 chrome.debugger CDP、106 张模型供应商卡片、有 Skills 机制。**但两条关键前提与描述不符:**

| 描述 | 实际核实结果 |
|---|---|
| MIT 协议 | **GPL-3.0-or-later**(v33.0.0 起因打包 Xapian/libzim WASM 改为 GPL;仅老版本是 MIT)。GPL 有传染性:衍生品必须整体以 GPL 开源,企业内部二开通常不可接受 |
| WXT + React 18 + TS + Tailwind | **纯原生 JavaScript MV3,无构建步骤、无框架、无 TS**(manifest 为静态文件,`src/chrome` 可直接 Load unpacked;monorepo 含 firefox/mcp-server 等多端) |

结论:fork 它 = 放弃 React 技术栈 + 背上 GPL 义务 + 在"少文件、大文件"的原生 JS 单体上改造。**两个采用理由均不成立,不采纳。** 可以借鉴其设计(Ask/Act 模式划分、供应商卡片交互),但不可拷贝其代码(避免 GPL 污染)。

### 2.2 推荐 fork 基座:nanobrowser

[nanobrowser/nanobrowser](https://github.com/nanobrowser/nanobrowser)(~14k star,活跃):

| 维度 | 核实结果 | 对本项目的意义 |
|---|---|---|
| License | **Apache-2.0**(已核实,修正 v0.1 中"MIT"的说法) | 可自由改造、可闭源内部分发 ✅ |
| 技术栈 | TypeScript + React + Tailwind,Vite + **CRXJS** + turbo | 与团队要求一致;CRXJS 基本停更,列 WXT 迁移决策点(见 6) |
| 页面控制 | Navigator 通过 chrome.debugger(CDP)执行真实输入事件 | 与"CDP 为主"决策一致,执行器是现成且经社区验证的 ✅ |
| 模型接入 | 多供应商 BYOK(含 Ollama 等),BaseLLMProvider 抽象 | M1 第一件事:确认/补齐自定义 OpenAI 兼容 baseURL |
| 架构 | Planner / Navigator / Validator 三 agent | 偏重;收窄为单 agent loop(保留演进位) |

与自研(v0.1)相比:fork nanobrowser 直接拿到最难的部分(CDP 执行器、流式模型层、侧边栏聊天壳),预计节省 1~1.5 周;代价是需要读懂并裁剪它的三 agent 架构。

### 2.3 仍保留自研方案中的设计

以下 v0.1 设计在 fork 基础上继续有效,作为改造目标架构:agent loop 宿主位置、双模页面读取、Skill 结构、存储层、安全层、目录规范(见 §4、§5)。

## 3. 总体架构

```
┌─────────────────────────────────────────────────────────┐
│  Side Panel(React,fork 自 nanobrowser,agent loop 宿主) │
│  ┌───────────┐ ┌──────────────────┐ ┌────────────────┐  │
│  │ Chat UI    │ │ Agent Loop       │ │ 配置中心        │  │
│  │ 消息流/工具 │ │ 模型决策→工具调用 │ │ 模型/Skill/系统 │  │
│  │ 卡片/确认  │ │ →观察→循环       │ │ Prompt/行为    │  │
│  └───────────┘ └───────┬──────────┘ └────────────────┘  │
└────────────────────────┼────────────────────────────────┘
                         │ chrome.* API(扩展页面直接调用)
        ┌────────────────┼─────────────────────┐
        ▼                ▼                     ▼
  Content Script    chrome.debugger(CDP)   chrome.tabs / storage
  读 DOM/正文        写操作主通道:可信输入    IndexedDB 会话/截图
  (Ask 类任务的主通道) 事件,attach/detach 管理  blob
        │
        ▼
   OpenAI 兼容 API(用户配置的 baseURL + Key,直连,SSE 流式)
```

- **Agent loop 宿主在 Side Panel 页面**(非 MV3 Service Worker):SW 空闲 30s 会被杀,长任务不可靠;Side Panel 常驻且能直接调用全部 chrome.* API。SW 只留薄职责(点图标开侧栏、角标、安装初始化)。
- **三 agent 收窄为单 loop**:nanobrowser 的 Planner/Navigator/Validator 合并为一个带工具循环的 agent + 可选"规划步骤"提示;复杂任务的多 agent 分工作为后续演进(搬 nanobrowser 现成分工即可)。

## 4. 核心设计

### 4.1 模型接入

- 沿用 nanobrowser 的 BaseLLMProvider 抽象;M1 首项工作:核实其自定义 OpenAI 兼容 baseURL 支持面(它已支持 Ollama,大概率开箱可用;若缺,按其接口补一个 provider,工作量小)。
- 供应商配置档:名称、baseURL、API Key、模型名/列表、默认参数、**是否支持视觉 / 是否支持 function calling** 标记;每会话可独立选模型;Key 仅存本地。
- v0.1 中的 Vercel AI SDK v6 方案降级为备选——仅在将来放弃 fork、回归自研时启用。

### 4.2 页面读取(双模,自 v0.1 保留)

| 模式 | 实现 | 用途 |
|---|---|---|
| 阅读模式 | content script 内 Readability 提取正文 → turndown → Markdown | 问答、摘要、翻译 |
| 操控模式 | DOM 遍历收集可见可交互元素,剪枝隐藏项,编号序列化:`[12] <button> "提交"`,上限 ~300 元素 / 8k token(即"DOM 蒸馏",与 nanobrowser 思路一致) | 点击、填表、翻页的元素定位 |
| 截图模式 | `chrome.tabs.captureVisibleTab` → base64 → 视觉模型 | 复杂页面辅助定位;供应商档需开"支持视觉" |

每次操作后重新捕获元素索引(ref 失效即重取);历史按 token 预算裁剪(上下文压缩放 M3)。

### 4.3 控制执行(CDP 为主,CS 为辅)

统一工具原语:

```
click / type_text / select_option / press_key / scroll / navigate / wait /
extract_data / read_page / screenshot / tabs(open|switch|close|list) / ask_user / done
```

- **写操作默认 CDP**:`chrome.debugger.attach` → `Input.dispatchMouseEvent / insertText / dispatchKeyEvent`,真实输入管线,填表/翻页/跨域 iframe 全可靠。策略可配:`自动 / 仅 CDP / 仅 CS`;站点级记忆。
- **CS 为辅**:读 DOM/正文(主通道)+ CDP 不可用时的降级(合成事件,输入用原生 value setter 兼容 React/Vue 受控组件)。
- 生命周期管理:任务开始 attach、结束即 detach;`chrome.debugger.onDetach`(用户手点"取消")→ 立即中止任务并提示;chrome:// 与商店页不可注入/调试,UI 明确提示。
- **失败重试**:动作失败(元素未变/未聚焦)→ 重捕索引 → 重试(默认 1 次)→ 仍失败则回报模型重新决策。

### 4.4 Agent Loop 与执行可视化

1. 组装:全局 System Prompt + 生效中 Skill prompt + 页面状态 + 裁剪后历史 → 流式调用。
2. 工具调用在聊天流中渲染为**可审计的动作卡片**("正在点击 [12] 提交按钮 · CDP 轨 · 230ms"),失败/重试标红。
3. 退出条件:模型 `done` / 直接回答 / 最大步数(默认 15,可配)/ 用户停止 / debugger 被断开。
4. `ask_user` 允许模型反问;配合高危确认形成人机协同。

### 4.5 Skill 与 System Prompt(采纳外部提案:prompt 片段 + 工具白名单)

```ts
interface Skill {
  id: string;
  name: string;
  description: string;
  mode: 'manual' | 'always';      // 手动选用 / 常驻注入
  prompt: string;                 // 注入的指令模板
  allowedTools: string[] | '*';   // 工具白名单(如填报技能禁用 screenshot/tabs,省钱且安全)
  modelOverride?: string;         // 可选:该技能指定更便宜/更强的模型
  builtin?: boolean;              // 内置技能不可删,可复制
  enabled: boolean;
}
```

- 内置技能起步:网页问答、页面摘要、表格提取、**自动填表**、翻页采集。
- System Prompt:全局基础 prompt 可编辑 + 每会话临时覆盖;存储 chrome.storage.local;JSON 导入/导出便于团队共享技能包。
- 演进位:按 description 做意图匹配自动选技能(embedding 检索)。

### 4.6 高危操作确认与安全

- 默认拦截:表单提交/下单/删除/支付类动作、跳转新域名、关标签页、剪贴板写、下载;全局与分类开关;确认卡片(允许一次 / 允许本会话 / 拒绝),阻塞 loop。
- Prompt injection 防护:页面内容统一标记为"不可信数据"注入;工具白名单;步数上限;高危默认人审。

### 4.7 数据与隐私

- IndexedDB(Dexie 4):会话、消息、工具执行记录(为**执行回放**留数据)、截图 blob、token 用量。
- chrome.storage.local:供应商配置、Skill、System Prompt、行为设置。
- 无遥测无后端;页面内容仅发给用户自己配置的模型服务。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| ~~WebBrain GPL 污染~~ | 已规避:基座改为 Apache-2.0 的 nanobrowser;WebBrain 只借鉴设计,**不拷贝代码** |
| CRXJS 停更 | M2 迁移 WXT;迁移前锁 Vite 版本 |
| CDP 黄条"正在调试此浏览器" | 内部工具可接受;任务结束即 detach 减少暴露时间 |
| 每 tab 仅一个 debugger(与 DevTools 冲突) | attach 失败提示关 DevTools 或临时切 CS 轨 |
| nanobrowser 三 agent 代码较重 | M1 即收窄为单 loop,保留其原语层不动 |
| 页面 Prompt Injection | 页面内容标记不可信;工具白名单;步数上限;高危默认人审 |
| MV3 CSP 禁远程代码 | 依赖本地打包 |
| 模型能力差异(视觉/工具调用) | 供应商档显式标记,不支持时自动降级纯文本流程 |
| token 成本 | DOM 蒸馏截断、历史裁剪、技能禁用无关工具、用量展示 |
